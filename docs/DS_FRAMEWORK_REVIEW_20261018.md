# 修改清单：让 DS 能照着已有方法做，也能处理新物体

这是待讨论的修改方案，还没有改新工作区。原来的 ds_control 保留给下一次对照实验。

这次最明显的问题是：我们把旧案例和脚本拿走了，又要求它自己完成观察、计算、控制和记录。它能把这些事情逐个做出来，但容易在中间算错，再围绕错误解释花很长时间。不能只靠一句“不要过度思考”解决，也不能把每一步位置和角度都替它规定好。

下面按八件事修改。先做前三件，试一次，再决定后面怎样补。

## 1. 把上次做成的方法交给它

上次它会去看成功案例和脚本，知道别人是怎样定位、抓取和旋转的。这次只有一些步骤名称和要求，具体怎么做仍要现场编。

把上次成功过程整理成一份短案例，保留关键图像、用过的方法、失败后改了什么，以及相关脚本。先给它最相关的一份，其他案例按需查，不让它先翻完整个日志目录。

脚本里的旧位置、旧 run 和颜色条件要拆出来。能可靠复用的计算和动作写成现成工具；暂时不能复用的，就明确是参考代码，不能原样执行。工具告诉它需要输入什么、会得到什么、什么情况下不能用。

做到：换个罐子，它需要重新看、重新选抓点，但不需要重新写通信、姿态转换和日志代码。

## 2. 让它少管框架的事

这次它花了不少时间研究回执格式、填写证据、处理哈希和导出文件。这些工作应该由程序处理。

日常入口只让它做几类事：看现场、读状态、发动作、查结果、结束实验。程序自动保存图像、动作和对应回执。模型只补一句动作依据，或者标出观察到的异常。

一次试验中的观察和小测试继续记在同一任务里，不动不动就退出、重新启动、写总结、打包。只有连接故障、用户停止或本轮结束时才处理会话收尾。谁占用设备、旧会话有没有退出，也由程序明确报告。

做到：它不用理解框架内部文件怎样关联，就能连续做事；停下来以后，记录仍然完整。

## 3. 把不会随瓶子变化的东西准备好

换一个瓶子，不应该连相机装在哪里、夹爪中心在哪里、旋转指令是什么意思都重新研究。

把设备安装关系、工具外形、坐标约定和已验证的操作方法单独保存。记录它们是怎么测的、适用于哪次安装。启动时检查是否仍适用；没有变化就复用，有疑点再补测相关部分。旧物体的位置、尺寸和抓点仍然重新观察。

不把历史数值直接当真，也不故意把所有资料清空。本次工具配置一度读成零，后来又恢复，程序应该先确认读数是否有效，再告诉模型设备发生了什么，不能把尚未刷新的值交给它自行解释。

做到：新物体需要新的场景判断，而不是每轮都从认识机械臂和相机开始。

## 4. 给常见问题准备几条可用的处理办法

它这次不断换测量方法，却没有稳定下来。不能指望它每次都能现场设计出正确算法。

先整理已经试过有效的办法。例如看不全目标时怎样改善视野；深度空洞很多时怎样换观察位置；抓取不稳时检查对准和夹持的哪些部分；安装关系确实不清楚时怎样补测。每种办法说明适用情况、操作入口和怎样判断有没有帮助。

让它根据现场选择，不规定所有物体都走同一条路。试了没有帮助，就回到当前问题，换一个已有办法；不要继续围绕一个猜测不断写新程序。确实没有合适办法时，记下缺口，留给维护阶段补工具。

做到：遇到常见失败，它有路可走；遇到新问题，也不会被固定流程卡死。

## 5. 把几种明显会误导它的结果挡住

这次罐高前后差很多、平面拟合抓到别的东西、旋转矩阵不成立，它仍继续从这些数值推结论。还用画面亮度变化判断机械臂转了多少。

能由程序检查的错误放进工具里检查。数据不足就返回“这次测量不能用”，并说明原因，不给它一个看似精确的数字。相对旋转由经过验证的代码完成，不让它每轮重写欧拉角公式。

需要模型看图判断的部分，要求它分清看见了什么和猜测是什么。数值互相矛盾时，先找哪次测量不可靠，不立即宣告物体无法翻转，也不立即认定控制器有问题。

做到：它不需要成为几何专家才能用对工具，但仍负责结合现场决定下一步。

## 6. 把“什么时候能放手”做成实际能用的办法

现在 skill 要求它确认触桌，却没有给它稳定可用的确认方法。只写“必须确认”解决不了遮挡，它可能一直停住，也可能自己编出一个确认理由。

先围绕现有罐子，把抓点、落放时的视野和松爪后的检查连起来试清楚。能从图像判断的，给出有效方法；需要别的接触信息的，先验证设备是否真的提供。估计高度可以帮助接近桌面，但不能单独当作已经获得支撑。

保留对抓点和观察姿态的选择，不写死高度和下降步长。遇到当前设备确实看不清、也测不出的情况，就如实记录这个能力缺口，不要求模型靠多想几轮解决。

做到：完成判据有实际办法支持，而不是只有一句要求。

## 7. 做完再整理经验，猜测不要直接传给下一轮

这次它把“旋转增益是 1.63”写成经验，下一轮又证明不是这样。反复写候选和导出，也打断了任务。

执行时只保存事实、尝试和结果。结束后再整理值得复用的内容，分清三类：已经用成的方法、失败时要检查的事情、还没弄明白的猜测。

有反证就修订或撤回原来的结论。下一次默认只提供适用的已验证方法；猜测留在记录里，不塞进操作 skill。一次成功可以成为案例，不能马上变成所有物体都要遵守的规则。

做到：经验越来越有用，而不是文件越来越多、互相矛盾的说法越来越多。

## 8. 保留分层，但不要让 DS 每次先研究整套分类

技能库仍然为“翻转不同物体”服务，不能写成一份越来越长的翻罐子说明书。

按四部分组织：

- 翻转任务：怎样算朝向变了、已经放下并独立站稳。
- 常用做法：例如抓起翻转再放下，或者需要先换一次抓法；说明什么时候适用。
- 操作工具：观察、定位、移动、夹持、旋转和检查，给出能直接用的入口。
- 具体案例：空罐、其他瓶子以及后续物体，各自保存有效做法和失败教训。

设备资料单独放，不混进每个物体的案例。入口先给 DS 当前最可能用得上的工具和案例，其他内容需要时再查。具体抓哪里、从哪个方向接近、是否需要重新观察，仍由它根据现场决定。

做到：它能从罐子案例学到办法，又不会把新物体都当成罐子。

## 怎么推进和判断有没有改好

第一轮先做第 1—3 项：补回成功方法、简化使用入口、准备设备资料。这部分完成后和用户讨论，再安排实验。不要同时重写所有感知和规划方法，否则成功或失败都很难知道是哪项改动造成的。

第 4—6 项根据实际卡住的地方逐项补，先解决已有物体的常见问题。第 7—8 项用于把经过验证的结果整理进技能库，再逐步换其他物体。

比较时看它有没有更快地抓稳并完成放置，花了多少时间在无效测量和写辅助代码上，是否需要人工点拨，失败后能不能回到任务。费用、总耗时和失败次数一起保留，不能只挑成功的那一段计时。

当前原工作区可用于重试新罐子；它与上次相似之处是能直接操作、能读历史方法和脚本，不是机械臂初始状态或物体完全相同。一次重试只能提供新的证据，不能单凭成败确定全部原因。
