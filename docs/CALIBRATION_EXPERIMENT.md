# 标定实验：从设备测试到后续任务可用

本文件用于首次安装、设备替换、相机重装、TCP/工具变更及相关配置复核。它是独立实验入口。标定实验看到 unverified 应开始补齐证据，不能套用翻转 skill 的“未标定就结束准备”。本轮不翻物体，也不测物体材料、质量或重心。

目标是交付可复算、可复用的安装与场景配置，并实际检查后续任务能读取它。DS 负责环境测试、采集准备、获批采集、计算、误差检查和材料整理；维护者负责采集路径复核、独立结果审阅及正式发布。用户发起标定实验已授权这些职责范围内的工作，不需逐个只读命令再问一遍。

## 1. 先确定本轮范围和任务

读取 devices/installation.json、devices/current.json、devices/active_calibration_task.json 以及已有标定报告。区分旧的设备身份摘要和 calibration_api.md 定义的完整数值档案：current.json 中有设备名称不等于它是完整 profile；不要反复拿身份摘要调用 profile-check。

| 变化 | 重新确认的内容 |
|---|---|
| 仅换待翻物体 | 不重做安装标定；检查安装与场景未变，再建物体模型 |
| 换相机、移动相机或支架 | 相机身份/流、手眼、受影响的工具包络及独立复核 |
| 换夹爪、指垫，或改变 TCP | 工具/TCP 身份、抓取中心、包络；重建或经验证换算受影响的手眼关系 |
| 换机械臂、移动基座 | 机器人身份、全部涉及基座的变换、场景与独立复核 |
| 移动桌面或障碍物 | 重新测场景；安装关系未变且验证通过时可复用 |
| 改相机分辨率、流、对齐或深度设置 | 对应流的内参/畸变/尺度和投影验证，复核相关标定输入 |

新设备不能沿用旧 installation_id 冒充同一安装。DS 在本轮 workspace 中准备新身份草稿，维护者更新正式安装版本。没有变化的部分可复用有来源且适用的证据，不为了“完整”重复测量。

同一安装已有 active、未 halted 且无未决动作的 calibration 任务时继续该任务；当前 DS 指针中的任务就是优先候选。先检查实际 state.json，指针的 awaiting_measurements 只是摘要。已关闭/故障任务不擅自恢复；设备身份改变则另建任务并关联前次记录。不存在可继续任务才调用：

```powershell
.\pipeline.ps1 calibration-task --installation <本次安装ID>
.\pipeline.ps1 brief <任务目录>
.\pipeline.ps1 status <任务目录>
```

以下命令均从本工作区根目录执行。若 PowerShell 脚本执行策略阻止启动，用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\pipeline.ps1 ...` 或对应 robot/check 脚本。尖括号是待填写参数，不能原样运行。

## 2. 环境测试：先能读，再准备移动

运行 check.ps1、pipeline.ps1 doctor，保存各自退出码和输出。前者验证硬件环境/来源，后者验证计算依赖；均不连接机械臂。确认使用当前副本的 .venv 与 .venv-pipeline，不混用另一个仓库的 Python。不要自行升级 SDK、改冻结配置或重装驱动来解决未知报错。

检查现有 session.lock、active.json、对应 PID、运行日志及外部控制软件占用。不杀掉别人的进程，不因路径里有锁文件就删除它。确认无冲突后，后台启动 robot.ps1 start，保存句柄、stdout/stderr，等初始采样 ready。start 是长期进程，不等其退出才继续；若用 Start-Process，指定隐藏窗口和不同的输出文件。start 会连接实机并采集，但不会主动移动或清错。

依次使用 robot.ps1 status、observe、gripper-check。打开实际彩色图，检查深度文件、有效区域、流配置与当前场景；保存状态、错误码、机械臂/TCP/夹爪信息和相机序列号。确认为空爪且未激活时才使用 activate-empty。先证明真实设备和数据出口可用，不运行未经审核的“随便动一下”测试。

现有状态回执未必含机械臂序列号，启动属性也可能是缓存。字段缺失时，记录准确缺项，请维护者提供官方只读查询适配或由人读取控制箱/铭牌；不要把 IP、型号或配置文件里的值当本次读取的序列号。安装版本是装配版本标识，不是要从设备猜出的测量值。

一个读数据步骤失败，先记录错误及其直接原因。只有修复或获得新证据后重试；不反复 doctor/profile-check。当前问题只影响一项时，继续其它独立的只读整理工作。

## 3. 授权申请：准备好具体内容再申请

| 情况 | DS 的处理 |
|---|---|
| 本轮环境自检、状态/图像读取、离线计算、workspace 草稿 | 已在标定任务范围内，自行执行；仍遵守工具权限机制 |
| 系统阻止访问项目目录或设备 | 用实际执行工具提供的审批机制申请具体路径/操作，说明用途；审批失败不能改用其它通道绕过 |
| 要移动机械臂取得标定视角 | 准备采集片段、真实起点、目标请求和场景证据，向配置中的教师/维护者申请路径复核 |
| 缺标定板尺寸、尺量数据或独立实物检查 | 把当时真正缺少的事项合并成一个明确请求，说明人需要做什么、如何回传读数 |
| 发布 verified 档案或改冻结配置 | DS 提交完整候选档案和复核材料，由维护者发布，不自行署名通过 |

不要只问“允许标定吗”。采集复核请求要包含：任务/安装 ID、空爪状态、最新回执、固定标定板与桌面照片、计划观察部位、实际目标和插补方式、已有几何信息及尚需教师现场判断的部分。首次未知手眼时，不依赖未知手眼生成扫描路径；由教师结合当前位姿与现场视图审核，或直接人工示教。DS 不从头实现 IK。

可以一次审核多个明确的采集片段，无需每步重复口头确认。申请记录与“已经获批”分开；不能自己给 reviewer_id、reviewed=true 填授权。计划字段见 [ACQUISITION.md](ACQUISITION.md)，purpose 使用 calibration_views。目标或审核起点改变时，原审核不再覆盖新计划。

```powershell
.\pipeline.ps1 request-teacher <task> --teacher human --missing <具体缺项> --question <具体问题> --segment <采集片段说明> --evidence <证据路径...>
```

此命令当前只写待处理请求，不会发送给人或 Astra。DS 必须在当前对话展示请求并等待实际回复，或者使用已配置且已获用户授权的通信通道；不能因为文件存在就继续动作。等待时可继续不依赖该批准的计算和材料检查。

取得真实审核后，按每段最新回执依次执行：

```powershell
.\pipeline.ps1 authorize-acquisition <task> --collection-plan <已审核计划JSON> --run <当前runID> --segment <段ID> --request <请求JSON> --from-result <最新成功回执> --output <单次带凭据请求JSON>
.\robot.ps1 execute <单次带凭据请求JSON> --from-result <同一回执>
.\robot.ps1 observe
```

采集许可允许在 calibration 未完成时执行指定视角采集，解决“必须先标定才能采集标定数据”的循环；它不允许直接执行翻转。实际结果未知时查原命令回执，不能重发。故障停止并报告，不自动清错、反向回放或松爪。人工示教则保存操作者、起止状态与采集图像；没有连续轨迹数据就不声称记录了完整路径。

## 4. 准备测量和采集能力

先取得固定刚性标定板的实际尺寸、角点定义及测量证据。可以使用合适的棋盘格等目标，但打印设定尺寸不等于实物尺寸；由独立尺量确认。缺少实物目标或量具时一次说明需求，不用瓶子尺寸或历史坐标代替。

手眼求解与目标位姿函数已实现；任意标定板角点识别和设备时间映射尚未封装成完整自动采集器。DS 可在 workspace/calibration/<本轮ID>/ 中写仅处理已有文件的角点检测、矩阵换算、误差汇总脚本，使用 .venv-pipeline，保留输入、版本、角点叠加图与输出。不能把合成数据当测量，不能修改冻结执行器；若需要实时采集接口扩展，应提交具体输入输出需求，由维护者接入同一会话，不能另开 SDK 控制连接。

现有相机日志保存设备时间、系统时间和主机接收时间，机械臂保存状态读取的单调时钟区间。这些时钟不会自动成为同一曝光时刻。先验证设备时间到主机共同时间的映射、缓冲延迟与误差，再生成 hand-eye 样本。不能把 received_monotonic_ns 当曝光时刻，也不能只写 timestamp_clock=shared_monotonic 就宣称同步。停稳采集有帮助，但不自动替代时间证据。该能力缺失时明确请求采集适配修复，继续可独立完成的尺量和档案整理。

## 5. 分项完成标定

| 分项 | 采集与计算 | 完成依据 |
|---|---|---|
| 安装身份 | 当前设备身份、TCP 配置、负载设置、工具和安装版本的原始读取/实物记录 | 身份来源明确，TCP/法兰坐标口径固定，配置哈希可复算 |
| 内参与深度 | 记录实际流、对齐方式、分辨率、畸变、SDK 深度尺度；至少两个不同距离的独立深度参考 | 投影所用内参与实际流一致；深度尺度误差满足预先规定的阈值 |
| 手眼关系 | 固定标定板，采集多方向旋转的静止样本；预先划分训练与留出验证 | 目标识别、时间、运动多样性、数值条件及留出误差均通过 |
| 抓取中心与工具包络 | 尺量/已知目标验证抓取中心，覆盖相机、支架和不同开口下的夹爪外形 | 工具坐标中的变换、尺寸、适用开口范围和误差都有来源 |
| 桌面与障碍物 | 用标定后的 RGB-D 测桌面及相关障碍，记录坐标系、平面方向、范围与不确定度 | 独立位置/距离复核通过；不能用同一拟合输出作独立真值 |

内部使用米、弧度、4×4 变换。固定关系是 `base_from_tool @ tool_from_camera @ camera_from_target = base_from_target`。明确 tool 是 controller_tcp 还是 flange；不能混用。设备深度回执中的 depth_scale_mm 转为米时记录换算，不能重复乘尺度。

手眼默认最低为 6 个训练视角和 3 个验证视角，至少两个非平行旋转方向；这是质量门槛，不是运动目标。采集前写下划分和质量阈值；不能用留出样本调参后仍称独立验证。查看角点叠加图和每个样本残差，针对遮挡、平面歧义、单轴退化等具体原因补采，不靠改阈值通过。

数值输入的完整字段见 [calibration_api.md](calibration_api.md)，不要猜 schema。现有 CLI 计算入口为：

```powershell
.\pipeline.ps1 compute target-pose <单帧目标输入JSON> <目标位姿输出JSON>
.\pipeline.ps1 compute hand-eye <手眼输入JSON> <手眼结果JSON>
.\pipeline.ps1 compute profile-check <草稿校验输入JSON> <草稿校验结果JSON>
```

profile-check 输入必须包含完整对象 `profile`、`current_installation` 和 `require_verified`；不是只传两个文件路径。草稿检查用 require_verified=false，profile.status=draft。这个检查仍需完整测量字段，并非验证一个空模板；通过只代表草稿结构与计算一致，不会自动完成实验。

桌面拟合、工具尺量和独立检查没有全部封装成单条 CLI。DS 可以对保存的点云做可复核的离线处理，但实际参考测量要有外部来源。无需测物体质量，不把 TCP 的已配置负载当本轮未知物体质量，也不擅自改负载参数。

## 6. 独立复核、提交与发布

准备 draft profile、场景记录、原始数据清单、逐样本误差、适用范围和未决项。用未参与求解和调参的目标，检验基座坐标位置/方向、抓取中心及工具包络；保留原始参考值、计算值和差值。只展示训练残差或手眼求解成功，不算独立物理复核。

把材料提交给维护者/人类复核。维护者按 calibration_api.md 使用 profile_content_sha256 生成几何内容哈希，写入实际 review，再发布 verified 档案。不要使用整个文件的哈希替代该专用内容哈希；文件证据 SHA-256 是另一回事。维护者署名不替代真正的检查。

用 `report-template calibration <报告JSON> --task <task>` 建报告。五项 checks 是 installation_verified、hand_eye_heldout、intrinsics_depth_verified、tcp_tool_envelope_verified、table_workspace_verified。每项引用对应原始证据与复核结论；报告中的 profile_path 指向完整档案，installation_path 指向实际安装身份记录。

```powershell
.\pipeline.ps1 submit <task> calibration <报告JSON> --evidence <完整档案> <安装记录> <场景记录> <其它全部依赖证据...>
.\pipeline.ps1 status <task>
```

提交前用 require_verified=true 再跑 profile-check。submit 要列出完整证据闭包，包括嵌套引用的图像、读数、输入结果和复核文件；不能只哈希最外层 JSON。场景不在完整 profile 的内置数值验证范围内，table_workspace_verified 必须另附场景及实际复核证据，不能把 profile-check 成功当桌面已验证。

calibration 模式通过后应得到 complete / calibrated，不能继续把这个任务当翻转任务提交 model。可以 finalize success 封存校准材料；这是标定成功，不是翻转成功。保留原始档案，维护者发布版本化配置和路径说明，不覆盖日志中的旧快照。

正式发布由维护者完成：同步主仓库与 DS 副本所需配置和全部证据，使用各自工作区可解析的路径，更新安装状态、标定任务指针、来源清单与版本。devices/current.json 是旧接口摘要，不能简单用另一种 schema 覆盖而破坏旧读者；维护者保持摘要与完整档案的对应关系，并明确完整档案的路径。DS 不改冻结文件来让 check.ps1 通过。

## 7. 用后续任务实际验收，而非只看 verified

标定实验的交付应包含一份 handoff.md，列出安装/场景版本、完整档案路径、可复用 calibration 报告路径、全部证据清单、有效开口与工作空间、失效条件，以及后续仍需处理的事项。

| 验收项 | 必须看到的结果 |
|---|---|
| 两个工作区的来源和依赖检查 | check.ps1、doctor 通过，配置/证据都在本副本内可读取 |
| 当前实际安装对应档案 | profile-check require_verified=true 通过，实际设备与安装身份未变 |
| 标定任务结束 | complete / calibrated，原始材料与复核可追溯 |
| 新任务复用 | begin 新建独立任务，提交有效 calibration 报告及证据后 stage=model；无需重复采集标定数据 |
| 几何接通 | 本次独立检查目标的相机点可转换到基座，与参考位置相符；桌面和工具包络在同一坐标中合理 |
| 后续操作边界 | 说明路径复核、物体范围声明等任务相关条件，不能把它们当标定已经一并批准 |

为验收创建的新任务标明 readiness probe，不执行抓取/翻转。完成复用检查后以 incomplete 封存该探针并说明“仅验证配置接入，未执行物体任务”，避免留下伪成功或悬挂任务。

若这一轮需要动作验证，应在审核过的空爪采集片段中取得新观测并检查几何，不额外发未经复核的移动。当前全臂路径仍是教师复核后端，标定不会自动把它变成全自主轨迹求解器；上线下一轮之前应明确谁负责审核候选路径。标定能解除标定阻塞，不能保证任意新物体都能成功翻转。

## 8. 结束与问题处理

普通翻转在标定缺失时交接；本标定实验则推进可执行的采集和计算，只有实际缺少物件、操作权限、采集接口或需要外部复核时才等待。每次请求说明具体材料/操作、已完成部分和继续所需答案，不反复报告“还没 verified”。

出错保存原始回执和当前状态，必要时 robot.ps1 stop。结束本轮自己启动的会话用 shutdown，确认进程退出并保留日志；不关闭他人的会话。不能因为一条命令超时就清锁或重发动作。

结果区分 calibrated、draft_pending_review、blocked_missing_measurement、blocked_adapter、failed_execution。后四者在现有 finalize 中分别用 incomplete 或 failure，并在摘要写明原因，不使用不存在的 outcome 枚举。摘要包含 text、interventions、failures、unresolved；记录起止时间、人工示教、补采原因、误差和待维护者发布事项。保留公开动作理由与工具记录，不要求隐藏思维链。
