# 与代表性机器人 Agent 方法的关系

本项目属于分层的工具调用机器人 Agent：语言模型选择技能和参数化策略，固定工具计算，执行器控制，观测决定阶段推进。按任务需要检查属性是工程设计，不是新范式或已验证的算法创新。“Agentic robot”不是一种统一架构，下面区分代表性路线。

| 路线 | 原方法的核心 | 本项目采用及差别 |
|---|---|---|
| [SayCan](https://say-can.github.io/) | 语言模型评价技能对目标的帮助，技能价值函数评价当前可行性 | 同样分离“有用”和“可执行”；目前用确定性检查及教师复核，没有训练成功率价值函数 |
| [Code as Policies](https://code-as-policies.github.io/) | 模型生成组合感知、控制 API 的程序，并可递归生成辅助函数 | 使用固定数值和控制接口；学生主要组织既有技能，不在每轮扩展执行器或递归实现底层算法 |
| [Inner Monologue](https://innermonologue.github.io/) | 场景描述和动作成功反馈支持闭环规划 | 明确输出当前阶段、缺项和回执；初版错误后停下，不照搬其自主恢复能力 |
| [ReKep](https://rekep-robot.github.io/) | 视觉关键点上的阶段目标和路径约束，通过优化生成末端动作 | 借鉴空间关系及阶段判据；当前采用实测刚体包络计算，不具备通用关键点生成、跟踪和完整约束优化器 |
| [Voyager](https://voyager.minedojo.org/) | Minecraft 自动课程、代码技能库、反馈修订和持续探索 | 借鉴经验检索和复用；物理实验由人选题，学生备材料，维护者审阅发布，不自动扩展任务或晋升技能 |
| [π0 等 VLA](https://www.physicalintelligence.company/blog/pi0) | 从机器人经验训练图像/语言到低层动作策略 | 当前无这类动作策略训练，用现有驱动和计算工具；不能将本项目视为 VLA 的同等替代品 |

本次改动的重点是任务契约。目标、适用范围、设备配置、技能需求和完成条件构成题干；只有会改变下一步的属性才进入信息采集。普通空刚性容器采用几何抓取翻转放置策略，材料和重心仍未知，但不作为该策略的前置条件。依赖质量/摩擦/重心的策略继续走测量路线。范围声明、物理测量和模型推测分别记录。

主流工作为分层、闭环反馈和空间约束提供依据，但没有直接证明“这套改动能让 DS 减少犹豫”。后者是待实机验证的假设。应比较同条件下的成功率、耗时、无效信息采集和人工介入，不将更短的回答或更少的停止直接视为进步。

当前差距仍在可靠感知、标定和路径检查：安装档案未完成实测发布，全臂路径需要教师复核，Astra 请求未接在线传输。不能靠调整提示词宣称这些能力已经具备。
