# Flip Anything：先建立证据，再推进阶段

目标仍是翻转不同物体。当前可运行的数值工具覆盖简单刚体、静态质量辨识和刚体落放仿真；布料目前接入表面运动表示。没有把一个空罐成功案例宣布为通用能力。

默认任务使用 [按任务需求的流程](TASK_DIRECTED_EXPERIMENT.md)，方法定位见 [代表性路线对照](AGENTIC_METHOD_COMPARISON.md)。六阶段保留记录兼容；properties 按任务契约选择适用性检查或完整测量，不再对每个空罐强制测质量。

## 实际结构

| 位置 | 职责 |
|---|---|

| `devices/` | 安装身份、待验证的标定档案、采集要求；只由维护者发布 |
| `logs/pipeline/TASK_*/` | 本轮阶段状态、内容寻址证据报告、动作凭据、教师请求和结束记录 |
| `logs/experiments/ds_control/` | 原始 RGB/深度、SDK 请求、机械臂和夹爪反馈、动作回执 |
| `logs/tasks/` | 原材料收集器关联的完整实验材料；保留原接口 |
| `logs/maintenance/` | 修改前备份、发布哈希、测试和变更记录 |
| `skill_harness/` | 既有三层技能库、旧案例及旧运行兼容层；不再承担新执行门槛 |

| `pipeline_tests/` | 数值反例、生命周期、执行绑定与仿真验证 |

主仓库 `G:\Flip Anything` 由维护者修改与发布；`G:\Flip Anything DS` 是学生独立副本，代码、虚拟环境与材料均在自己目录。两者仍连接同一台机械臂，使用同一设备互斥协议。目录隔离是协作约定与来源检查，不是抵御任意恶意代码的操作系统沙箱。

## 六个阶段

| 阶段 | 做什么 | 通过条件 | 缺失时 |
|---|---|---|---|
| 标定与场景 | 核实安装、TCP、相机流、深度尺度，标定手眼与工具包络，测桌面和障碍物 | 独立留出样本验证、安装身份绑定、实物交叉检查；档案为 verified | 留在标定，开专门采集任务 |
| 建模 | 分割当前对象，多视角合并、配准和拟合；保留未见区域 | 米制坐标、有效配准、抓取与支撑部位的可观测几何 | 改善观察；复杂/非刚体交教师，不用包围盒冒充完整形状 |
| 策略适用性 / 物性 | 默认核对实验范围与当前观察；研究策略才测物性 | 默认有对应对象的原始范围声明且无观察矛盾；研究模式要求实测 | 仅补影响当前策略的缺项，不把未知改成已知 |
| 规划 | 检索已发布经验，按当前物体修改流程；计算抓点、翻转与落放几何 | 支撑、工具净空、实际插补路径与障碍物均有对应证据 | 选择其他抓点/观察，或教师示范；学生不从头编写 IK |
| 执行 | 既有驱动逐段执行，检查新鲜回执、任务与方案版本 | 每段结果已知；倒置、触桌、释放、退开后独立稳定均有证据 | 停止，保留夹持，叫人；不自动清错或反向回放 |
| 材料处理 | 保存原始对话、代码、图像、工具事件和结果，维护者审阅 | 成败与干预写清，证据哈希可核对；失败也能收尾 | 保留 incomplete/unknown，不改写成成功 |

`pipeline.ps1 status <task>` 给出当前阶段与缺口。计算输出不会自己把阶段改成完成；提交报告时检查身份、哈希、依赖和数值结果。上游结果替换后，后面的报告失效。事实性检查仍需真实观测或教师复核；字段写成 pass 不代表软件看懂了现场。

## 标定要固定哪些东西

统一使用 `a_from_b` 表示把 b 坐标转到 a；模型内部米/弧度，控制器接口毫米/度。唯一转换在 `controller_boundary.py`。TCP 和法兰不能混用。保持静止时采图，并记录共享时钟中的曝光/姿态时间；旧日志里相机时间戳为零或仅采集前后依次读姿态，不能冒充已同步。

长期配置包含安装身份、当前 TCP 配置哈希、相机序列号/流/内参/畸变/深度尺度、手眼、抓取中心、相机/支架/不同开口下夹爪包络、误差范围。桌面和障碍物按场景保存。换瓶子只重建物体模型；拆相机、改 TCP 或相机流时才使相关安装标定失效。旧成功案例的拟合结果留作参考，不自动升级为 verified。

本次已实现标定数值算法和验证契约。真实角点提取、可靠曝光与机器人时钟对应、实测标定板、工具包络和独立物理复核要在专门采集任务完成。初始采集视角由教师复核后通过 authorize-acquisition 执行，或由人示教并记录；程序不会自动生成未知安装下的采集路径。见 [标定接口](calibration_api.md)。

## 建模与质量测量

Open3D 多视角配准有实质算法调用，配合已知手眼位姿作为初值；不能让 ICP 任意漂移来掩盖标定错误。圆柱和盒体拟合检查残差、视角和覆盖，圆柱端部必须有独立实测位置。透明、反光、遮挡处保留未知。MoSE3 导入官方 predictions.npz，并要求独立的米制尺度与世界坐标对齐；输出只是表面轨迹，未实现布料材料辨识和软体仿真。

质量分布先用简单静态方法：称重部件合成；多支点称重；有经标定的力/力矩传感器时做多姿态重力最小二乘。一次支点称重只能获得垂直重力方向的重心投影，多朝向且质量不变才能合成三维重心。没有测量就记未知。本系统没有假定 xArm 6 已有可靠六维力传感器。

MuJoCo 使用给定质量、重心、惯量、摩擦运行刚体落放。它验证这些参数假设下的行为，不从网格反推出真实密度或内容物。目前只实现盒体和圆柱落放实验；不是完整 xArm、夹爪接触或液体仿真。见 [建模与物性接口](modeling_physics_api.md)。

## 规划与执行的边界

`propose_rigid_flip` 计算当前抓取关系下的倒置落放位置、工具最低点和保守抬升建议。它会拒绝落放时相机/夹爪穿桌的抓点。球包络只覆盖给定工具和物体相对桌面的几何；不会证明机械臂各连杆、其他障碍物或关节插补的全过程无碰撞。

当前没有安装完整机械臂 URDF 碰撞/轨迹求解适配器。全臂路径检查仍是明确的教师复核项，必须注明实际插补方式及对应证据；复核绑定当前任务、对象、安装、几何结果与有序动作请求。控制器 IK 可解只说明目标可达，不能充当全路径净空证据。没有这项证据时，状态停在 plan。下一步应在标定任务固定机器人模型与场景障碍物，再接入一个成熟轨迹检查器；不能让 DS 为了继续而自行填“通过”。

状态机负责证据顺序；底层 session 负责动作期反馈轮询、夹持丢失、控制器错误和 STOP 中断。不是只有动作凭据超时一个检查，也没有宣称已经实现独立硬实时监督器。进程卡死/电脑断电的保护仍由控制器及现场急停承担。

新版移动/夹爪请求必须带单次凭据，绑定原请求、当前 run、方案版本、最新回执及顺序。动作结果未知就查原回执，不重发。打开可能持物的夹爪要检查新鲜支撑证据，不只看阶段名称。失败后记录教师请求，流程退回待处理；没有自动物理恢复、自动松手和自动清错。

## 教师与学生材料分别处理

教师语言建议只是一项提案；实际示范才包含动作、反馈、接触、阶段和结果。先按阶段/接触标记分段，再在标定、时序和物体位姿可靠时提取物体坐标系关键点。没有这些条件就保留原轨迹而不宣称可迁移。流程借鉴 MimicGen 的物体相对分段，但没有把轨迹变换当作执行保证。

学生材料保留失败前缀、重试、人工介入和未经验证的解释。总结器按事实、假设、适用条件和反例整理，借鉴 DROC 的纠正整理和检索思路。第一版是可检查的规则处理，没有把它冒充已经训练好的自动总结器。见 [经验接口](experience_api.md) 与 [研究依据](experience_research.md)。

技能仍分为“翻转”的目标与验收、抓起翻转/滚动/折叠等方案族、观察/抓取/落放等能力；空罐属于具体对象条件的特化。经验检索先匹配安装、对象家族、目标和方案适用条件，再排序。未发布、已撤销或不适用的记录不能被检索为正式经验。维护者审查、发布和撤销；DS 只准备材料。

教师请求记录缺口、现场快照和需要示范的片段。没有配置 Astra 适配器时保存 pending/sent=false，并明确请求人工转交；不会把写文件说成已经呼叫 Astra。可见原始对话、动作依据摘要、工具输入输出都保留，不索取模型未公开的内部推理链。
