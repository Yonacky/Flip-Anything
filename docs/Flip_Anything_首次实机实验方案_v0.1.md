# Flip Anything 首次实机实验方案

日期：2026-10-14。状态：待执行的探索实验，不是结果报告。

已确定：人遥操作同一台机械臂，记录相机和机器人状态；另一条经验由 Astra 编码控制该机械臂产生；Astra 分别整理成 skill，再分别交给同一个低成本模型执行，接收端暂定 DeepSeek。具体模型版本、相机、机械臂和API以开跑前登记为准。

## 1. 这次只回答三个问题

首先，DeepSeek 在得到 skill 后，是否比只拿到任务和机器人接口更容易完成翻转？其次，两路 skill 的效果是否不同？最后，技能迁移失败主要发生在感知、策略理解、代码实现还是实际接触控制？

这次比较的是“人类遥操作经验经 Astra 整理”和“Astra 自身执行经验经 Astra 整理”这两条生产路线。它不能单独证明人类思维优于模型，也不能证明 DeepSeek 获得了人类的泛化能力。单日小样本首先用于检验流程、发现差异和决定下一步。

第一次不训练模型权重，不做RL，不搭复杂检索库。保留可用于后续学习的原始记录。

## 2. 开跑前填定的实验卡

| 字段 | 当场填写内容 |
|---|---|
| experiment_id | 固定且唯一的实验编号 |
| 机械臂、夹爪、工具、控制模式 | 型号、配置和版本 |
| 相机与记录频率 | 视角、分辨率、时间戳来源、实际采样率 |
| 人类操作者 | 匿名ID、遥操作熟悉程度 |
| Astra采集/整理端 | 精确模型ID或界面版本、推理设置、日期 |
| DeepSeek执行端 | 精确模型ID、服务商/端点、推理与采样设置、上下文上限 |
| 视觉输入方式 | 直接图像输入；或固定感知模块提供结构化结果 |
| 共用接口 | API文档与执行器版本、坐标系、单位、反馈字段 |
| 测试预算 | 每回合时间、工具调用数、物理动作边界 |
| 物体与初始状态 | 编号、照片、尺寸、质量（能测则测）、目标面、摆放参照 |

不要仅写“用了DeepSeek”。先验证选定端点能否接收所需图像、使用工具并生成接口调用。如果它不具备直接视觉输入能力，三组统一使用同一个固定感知前端，并称为“DeepSeek＋感知前端”；不能在其中一组临时让 Astra 帮它看图。感知前端只给可观测状态，不输出翻转策略。

先做一次接口冒烟检查：读取图像、读取状态、调用已有的低风险基础动作、接收执行结果、保存日志。此处只排除系统故障，不用盲测物体调试。

## 3. 物体、任务和成功定义

首轮选一个开发物体 D，另留两个测试物体 T1、T2。D应能在现有平台上做出明确翻转，既不是一碰就能翻的玩具任务，也不应难到两路都无法产生可用经验。T1改变尺寸或外形中的一个主要因素；T2改变一个可能影响接触策略的物理属性。不要同时更换夹爪、工具和工作台。

T1、T2在skill冻结前不用于源轨迹采集、提示词调试或skill修订。测试时学生会看到当前物体，这是正常输入；“未见”指没有用它开发技能。

预先写清任务，例如：“将物体从指定初始面翻到目标面，在指定桌面区域内稳定保持3秒。”如果实际是锅内翻转，则补充“最终留在锅内”；如果是桌面翻转，不套用锅内条件。3秒是首轮建议值，可以在开跑前统一修改。

每个测试物体预设两个可重复初始状态 P1、P2，用照片和桌面参照重置。姿态变化不应偷偷引入另一种任务。结果以外部视频和预先判据确认，模型自报完成不直接算成功。

## 4. 先采两路源经验

### 4.1 最小采集安排

两路只在D上采集。建议每路最多6个回合，覆盖两个初始状态，每状态最多3次尝试；达到预算即结束，不为了凑成功无限延长。每回合时限在开跑前统一确定，首轮可暂设120秒，并将初始化/重置时间另记。这个预算是流程建议，不是统计充分性结论。

H路由人遥操作。A路由Astra根据相同任务、图像、机器人状态和API编写/调整程序。两路独立开始，Astra不读取H路视频、解释或成功代码。提前固定采集顺序；记录操作者是否已经看过另一条路线，无法避免的观察影响写入日志。

A路可在自己的回合之间利用反馈修正，但不能获得人类的操作建议。人负责重置和已有安全边界内的操作监督；一旦提供策略提示或接管，该回合标为“人机协作”，不再算纯A来源，仍完整保留。不要事后把协作记录删掉当作没有发生。

如果某一路完全未成功，也照常保存它的材料并标注。可以测试其经验是否有帮助，但不能称其skill为“已验证技能”。若两路都不成功，当天应转为采集和任务适配调试，不把学生失败解释为知识迁移失败。

### 4.2 两路都保存什么

| 数据 | 最小要求 | 用处 |
|---|---|---|
| 视频/图像 | 保留原始记录、帧时间戳、固定视角 | 看接触、姿态变化和最终结果 |
| 机器人状态 | 实际可读的关节/末端位姿、夹爪状态、时间戳 | 重建动作和定位错误 |
| 动作指令 | 遥操作指令或程序控制指令及时间戳 | 区分意图和实际执行 |
| 执行事件 | 调用、异常、停止、人工介入、重置 | 判断是谁解决了问题 |
| 回合结果 | 成功/失败/基础设施异常、终止原因 | 保持一致分母 |

如果有力/力矩或触觉就记录；没有就写“未测量”，不能把电流或视觉推断当作实测接触力。时间戳应能对齐，记录时钟来源和已知偏移，不要求临时为首轮重做整套采集系统。

H路额外保存操作者的简短回顾：观察到什么、原来打算怎么做、什么时候改变计划。A路保存实际可取得的对话、生成代码、工具调用和执行反馈，不要求或假设可以获得模型隐藏推理。

## 5. Astra怎样分别生成skill

### 5.1 主实验先对齐输入材料

主实验让两次整理看到相同类型的信息：任务、API、固定方式抽取的多视角图像/关键帧、状态和动作记录、回合成败与事件。所有源回合都进入材料清单，不只挑成功片段。日志过长时使用相同抽样/摘要规则，并保留原始文件。

主实验暂不提供H路口头回顾，也不提供A路源代码和决策解释，避免把“人类动作视频”与“模型现成程序”混为同一信息条件。采集时保留这些材料，是为了后续明确增加解释或代码的对照。

人类连续遥操作与模型程序动作的时间粒度仍可能不同。统一转换为带时间戳的观测—动作—结果记录，只能减少混淆，不能宣称两路信息完全等量。额外报告各路回合数、成功数、视频时长、材料长度。

### 5.2 整理规则

分别开两个全新Astra会话，用匿名来源包X、Y和同一提示词整理；不让它读取另一包。平台已有API知识可以共用，不能加入额外任务解法。固定模型、推理设置、工具和材料预算，每路一次生成。若产物格式损坏，只允许相同的格式修复；不让人按自己偏好的策略润色其中一份。

先采用纯文字skill，允许坐标、单位和必要公式，不附可直接运行的任务程序。两份使用同一结构和上限，例如正文不超过2000个中文字；不用填充文字硬凑等长，实际token数另记。超长时使用同一压缩提示，保留前后版本。

统一整理提示词：

```text
你将根据一组真实机械臂执行记录，为另一个能力较弱的模型整理翻转技能。
仅使用本包记录和共用机器人API，不读取其他经验，不调用机器人补做实验。
不要根据来源身份评价策略。成功、失败和不确定部分都必须保留。
输出一份文字skill，包含：
任务与成功条件；适用/不适用条件；执行前需要观察的量；
动作阶段；每阶段结束判据；有证据的参数及单位；
常见失败与恢复；迁移到新物体时应重新判断什么。
每项关键经验附源回合ID和时间段。
区分“记录中验证过”“从记录推断”“未知”，不得补造力、摩擦或阈值。
未验证的迁移建议不能写成保证有效的规则。
正文不超过2000个中文字，不提供完整可执行任务代码。
```

此后冻结 `skill_H_v1.md` 和 `skill_A_v1.md`，记录文件hash及来源清单。可在本地保存生成提示、材料和原始回答，无需新建技能管理平台。

## 6. DeepSeek正式测试

### 6.1 三个条件

| 条件 | 学生拿到的内容 |
|---|---|
| B0：无skill | 任务、当前观测、共用API与运行约束 |
| BH：人类来源skill | B0全部内容＋skill_H_v1 |
| BA：Astra来源skill | B0全部内容＋skill_A_v1 |

三组使用同一DeepSeek版本、相机/感知输入、执行接口、代码校验、时间和工具预算。共用执行器可以包含基础动作和通用运动规划，但不能偷偷包含完整翻转解法；如果已有这种函数，应明确记录，后续增加固定调用它的对照。

每个物体—姿态—条件开启新会话，清空临时脚本和任务记忆，不共享上一组的执行结果。学生在回合内可看反馈和改代码，三组使用相同权限；不能获得人的策略提醒或Astra在线修复。

统一学生提示词：

```text
根据当前观测、任务定义和提供的机器人API完成翻转。
如果附有skill，可据当前物体判断其适用性；skill中的推断不是已验证事实。
你可以在本回合内根据工具返回调整程序。不得访问其他条件的记录。
只通过已提供的执行接口操作，遵守给定动作边界和回合预算。
最终输出你的完成判断；实验成功与否由统一外部判据确定。
```

### 6.2 首轮18个回合

3个物体（D、T1、T2）×2个初始状态×3个条件＝18个回合。D用于检查原任务复现，T1/T2用于探索迁移，分开报数，不合并成“泛化成功率”。

同一物体—姿态构成一个测试区组，每次恢复相同起点。六个区组分别使用三条件的六种排列，各出现一次；开跑前随机决定区组对应哪种排列并保存。这样避免一种条件总在工作台最干净或操作者最熟练时执行。

18回合只用于首轮诊断。每条件只有6回合、陌生物体只有2个，不做显著性或普遍优势结论。时间不足可以停在完整区组结束处，并报告已做多少；不能只留下某组成功的区组。

### 6.3 成败和异常怎样处理

主结果是时限内无策略帮助完成目标。安全监督、机械臂停止和辅助完成都记录，人工接管不算自主成功。回合内允许恢复时，另外记录第一次翻转动作是否成功和总尝试次数，避免把反复试到成功当一次成功。

预先定义可以重跑的基础设施异常，例如相机断连、日志缺失或控制服务崩溃；保留原记录，并按同一规则重跑。模型生成错误代码、选错参数、超时及普通动作失败属于实验结果，不以“异常”名义重跑。

## 7. 主测试后才能做的救援实验

主轮完成前不修改skill。若学生失败，先归因，再只选择一个最有信息量的补充实验：加入来源解释；加入Astra根据该来源材料生成的参考代码；或在开发状态上允许Astra按学生失败修订skill。

补充轮每种条件重新开会话并从同一初始状态开始。只测试失败条件的救援可以用于调试，但不能与未接受救援的另一条件比较后宣称来源优势。想比较文字＋代码，BH和BA都应有独立对应版本，且代码来源和验证次数一致记录。

只要使用了T1/T2的失败来改skill，它们就成为开发/验证对象。修订后的泛化结论必须换新物体测试。

当天应得到：两路完整经验包、两个可追溯的冻结skill、三组独立学生轨迹、一张原始结果表，以及下一轮只改什么的决定。

若B0已经全部成功，说明首轮任务无法辨别skill收益，应扩大物理变化。若两种skill都失败，先看接口与执行能力。若只有代码辅助有效，说明代码是重要载体。若BH与BA有差距，先检查源经验成功率和信息差异，再用更多对象、重复整理和独立采集验证。
