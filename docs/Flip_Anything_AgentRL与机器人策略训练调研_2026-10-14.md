# Flip Anything：Agent RL 与机器人策略训练调研

调研日期：2026-10-14。本文依据论文、作者项目页和官方代码；数字是作者报告结果，未由我们复现。版本明确标出的论文按该版本核对，不混用后续版本或排行榜数字。本报告补充并审视 v0.2，不代表已经实施训练或取得机器人实验结果。

## 1. 判断：需要补上学习闭环，而不是简单换一个“更先进”的模型

我们的现有流程——人和顶级模型解决新物体、整理 skill、交给便宜 VLM 执行——适合作为经验生产和快速原型流程。但如果长期只修改文字、代码和参数，既不训练接收经验的模型，也不学习接触动作，就可能形成一个越来越依赖人工维护的系统。这个担忧成立。

目前真正缺少的，是比较同一批经验用不同方式交给学生后，哪种方式最有效：上下文中的技能库、教师交互轨迹的监督微调、根据实际结果进行 RL，以及直接学习机器人动作的 policy。不能事先把“不更新权重”当作目标，也不能把“用了 RL”当作进步。

已有证据支持三种不同路线：训练 Agent 学会生成和调用技能；利用示范和纠错训练动作策略；在已有强策略上用少量真实交互优化困难动作。它们分别解决决策、经验吸收和物理执行的问题。下一步应先定位我们失败在哪一层，再决定训练哪一层。

## 2. 先区分训练对象

| 路线 | 模型输出 | 训练数据 | 反馈是什么 | 对我们的意义 |
|---|---|---|---|---|
| Agent SFT / 蒸馏 | 代码、工具调用、子任务 | 教师的完整交互记录 | 模仿经过验证的决策与恢复过程 | 教学生如何使用我们的接口与经验 |
| Agent RL | 代码、工具调用、子任务 | 学生与可执行环境反复交互 | 最终任务完成、耗时、错误等 | 改善策略选择、参数选择和失败恢复 |
| 机器人模仿学习 | 连续动作或动作序列 | 图像、本体状态、示范动作 | 与示范动作匹配 | 学习难以用语言完整表达的操作 |
| 机器人 RL | 连续动作或动作序列 | 真实或仿真交互、示范、纠错 | 物理任务成功和执行效率 | 改善接触、翻转时机、稳定性 |
| 冻结主干＋小策略 RL | 对原策略动作的调整或替代动作 | 基础策略经验＋新任务交互 | 任务结果 | 不重训整个大模型，针对瓶颈学习 |

Policy 只是决策规则的统称，并不与 Agent 对立。关键是动作空间：生成一段 Python 和输出下一段机械臂运动，所需数据、奖励和实验环境完全不同。

## 3. Agent 侧：怎样把经验变成模型能力

### 3.1 SAGE：直接训练“会使用技能库的 Agent”

基于 Qwen2.5-32B-Instruct。先用 Claude Sonnet 3.5 V2 生成的 1,129 条有效经验做 SFT，再用技能增强 GRPO：前一任务生成技能，后一任务复用；奖励同时考虑任务完成和成功复用。RL 使用训练集中难度 1、2 的 24 个场景，每步 384 条 rollout，开发集选择第 75 步 checkpoint。

| AppWorld 指标 | 仅技能库 Agent | ＋SFT | ＋SAGE | 无技能库 GRPO |
|---|---:|---:|---:|---:|
| Normal 单任务完成率 | 30.7% | 55.2% | 72.0% | 69.2% |
| Normal 三任务全完成率 | 19.6% | 41.7% | 60.7% | 51.8% |
| Challenge 单任务完成率 | 15.3% | 37.2% | 50.1% | 40.7% |

Normal/Challenge 分别 168/417 个数字任务，结果平均三次评测。默认知道场景分组，技能仅在同场景连续三个任务间共享；不是机器人实验，也不是任意陌生技能库迁移。SFT 是额外教师监督，因此不能把对 GRPO 的全部提升归因于技能库。

对我们的直接启发：应测试“学生能否学会使用技能库”，不能只测试“技能库写得是否完整”。

来源：[论文，§3–4、表1、附录E–F](https://aclanthology.org/2026.acl-long.69.pdf)。

### 3.2 Agent Lightning：在真实软件执行环境中做结果驱动 RL

2026-09 官方 MoE 示例使用 Qwen3.5-35B-A3B、SWE-smith 和 4×B200。Agent 在隔离仓库中改代码、运行测试，获得任务奖励；当前公开训练代码使用 GRPO，配置包含每组 8 次采样、32,768 模型上下文上限和 1e-6 学习率。R3 是 MoE 路由重放机制，不是任务奖励算法。

官方报告在 SWE-bench Verified 全部 500 题、官方测试框架下，基础模型 239/500＝47.8%，训练第112步 308/500＝61.6%；第176步为60.6%。报告的“1,792 examples”按每步16个训练样例计算，不等于总交互轨迹，更不等于从零训练所需数据。

复现限制：公开 main 配置会变化，当前默认 batch 与成绩页统计口径不同，不能把当前脚本全部默认值宣称为该成绩的准确运行配置；需固定提交和运行日志。成绩页未完整给出评测上下文、重复种子等细节。

来源：[官方成绩与条件](https://microsoft.github.io/agent-lightning/stable/76-example-coding-agent-moe/)、[执行环境与奖励流程](https://microsoft.github.io/agent-lightning/stable/75-example-coding-agent/)、[训练代码](https://github.com/microsoft/agent-lightning/blob/main/examples/swe_smith/train_smith_agent_megatron.py)。

对我们的启发：要训练代码 Agent，需要能执行、判分和重置的机器人任务环境。代码不报错只是接口正确，物体是否真的翻过来才是任务结果。软件测试可以并行复制，真实接触过程则不能直接照搬这种规模。

### 3.3 SERA：强教师轨迹蒸馏本身就应成为基线

SERA-32B 用 GLM-4.6 教师生成的 200,000 条代码 Agent 轨迹微调 Qwen3-32B，不做 RL。教师先修改仓库，再根据修改描述重现变更，以补丁行级召回做软验证。训练3轮、最大序列32,768、学习率1e-5；论文报40 GPU-days，不能视为包含教师数据生成的全流程成本。

SWE-bench Verified：32K评测上下文为49.5%±1.9%，64K为54.2%±1.4%，均按三次随机种子评测。基础Qwen3-32B在32K为24.4%。同一权重增加推理上下文也能涨分，因此不同上下文的数字不能直接比较训练算法。

来源：[论文，表1、附录E](https://arxiv.org/html/2601.20789v1)。

对我们的启发：教师成功之后，应保留“观察—决策—代码—执行反馈—修正”，而非只保留最终脚本。但机器人接触动作必须通过真实执行或可信环境验证，补丁相似之类的软验证不能代替物理成功。

## 4. 机器人侧：怎样训练真正完成动作的策略

### 4.1 HIL-SERL：已有真实机器人翻转结果，必须作为近邻基线

视觉采用 ImageNet 预训练 ResNet-10，动作策略用基于RLPD的离线/在线数据混合RL；成功分类器提供稀疏奖励。通常结合示范和人工接管，但动态翻转任务没有沿用常规在线纠错。

| 锅内翻转实验 | 作者报告 |
|---|---|
| 初始示范 / RL数据 | 20条 / 25,000个状态转移 |
| 在线训练时间 / 硬件 | 1小时 / 单RTX4090 |
| 控制 / 回合上限 | 10Hz；100步；输出三个力/力矩分量 |
| 测试 | 100次；翻到另一面且留在锅内 |
| 成功率 | RL 100%；BC 46%；Diffusion Policy 56% |
| BC、DP示范量 | 各200条 |

正文说物体在锅内随机放置，附录配置却写 Randomization range=None；不能据此宣称广泛随机化，更没有证明陌生物体类别泛化。100/100只是这组测试结果。训练时间包含脚本动作、rollout、预定停顿和计算，不是从安装机器人开始的总开发时间。

来源：[论文，表1、§4.2–4.3、附录A.11](https://arxiv.org/html/2410.21845v1)。

对我们的启发：单个物体翻转的高成功率已不足以构成研究目标。需要回答新物体、新接触条件下，经验是否可复用；也应允许一个小动作策略取代反复手调的轨迹。

### 4.2 π*0.6 / RECAP：示范、纠错和自主经验一起训练VLA

RECAP先做离线RL预训练和任务示范微调，再采集自主与人工纠错轨迹。价值模型估计剩余完成步数，利用优势标签训练条件策略；不是直接套用标准在线PPO。

具体追加数据：咖啡任务429条纠错＋414条自主轨迹；T恤/短裤每轮300条自主轨迹、4台机器人；多样衣物450条自主评测轨迹＋287条纠错。它们都是已有基础模型上的追加经验，不是全部预训练数据。

测试包括真实咖啡、折衣和纸盒任务；T恤/短裤要求200秒内折好并放置，纸盒整体600秒。除多样衣物外，最终成功率在90%以上；多样衣物和咖啡吞吐量相对离线RL＋SFT超过翻倍。成功由人工按质量项标注。多样衣物的主要定量结果测困难的纽扣衬衫，不能当作全部11类衣物的平均。

来源：[论文，§V–VI、附录F](https://www.pi.website/download/pistar06.pdf)。公开正文与附录对纸盒600条数据的名称存在不一致，本文不把它无条件算成“600条示范”。各主图独立最终测试分母未在本次核查中完整核实，不补猜。

对我们的启发：失败轨迹也值得保留。判断失败后只改skill、丢掉执行数据，会失去可用于价值学习和策略改进的信息。

### 4.3 RL Tokens：冻结VLA，用小策略优化困难接触阶段

RLT先训练一个压缩VLA内部信息的表示接口，随后冻结表示，训练较小actor/critic。actor还接收VLA原动作，以动作块为单位优化，并可使用人工纠错。测试电动螺丝刀、扎带、网线、电源插头四类精细操作，关注任务关键阶段。

最容易误读的数字是网线插入：15分钟实际机器人数据，对应约2小时总训练时间，其余是重置等开销。作者报告关键阶段最高约3倍提速；并不是15分钟从零学会完整新任务。基础VLA已经能完成大部分前序动作。

来源：[官方方法与实验说明](https://www.pi.website/research/rlt)。论文PDF本次未成功取得，未核实的示范总量、逐任务测试次数和精确成功率不填数；这项作为机制参考，不作为已完整审计的复现配方。

对我们的启发：若失败集中在接触点微调、抬起时机或翻后落稳，可以固定上层策略，单独学习这段控制，而不是让大模型每次重写整个程序。

### 4.4 SimpleVLA-RL：仿真高分与真实可用之间仍有距离

这里核对v1：改造OpenVLA-OFT为动作token预测，用SFT初始化，再以任务成败做GRPO。输入和输出头与原始OFT不同，表中91.0%不是官方checkpoint直接复测值。

| 条件 | 数据与测试 | SFT → RL |
|---|---|---:|
| LIBERO四套任务 | 每任务50个留出场景，仿真 | 91.0% → 99.1% |
| 真实双Piper迁移 | 每任务1000条仿真SFT轨迹＋1000个RL仿真场景；4任务各50次真机测试 | 17.5% → 38.5% |

真实测试为干净桌面、未见背景，训练不使用真机示范。论文表6与正文对任务名称、个别基线数有不一致；此处采用表6均值，不把“场景数”当总rollout数。真实结果说明有收益，但远未达到仿真的99%。

来源：[论文v1，§4.1、§5.3、表2与表6](https://arxiv.org/html/2509.09674v1)。

对我们的启发：可以把仿真作为训练工具，但“仿真翻得好”不能替代真实新物体评测。尤其要验证摩擦、形变和接触几何造成的迁移误差。

### 4.5 MolmoAct2：开放训练路线，也暴露真实部署难度

训练采用离散动作预训练，再加入flow-matching动作专家，最后面向目标任务微调。公开YAM子集有34,500条示范、720余小时、28余类任务，另混合DROID、SO100/101等；720小时不是全部数据。

真实双臂/移动YAM的8个部署任务每任务50次评测，均从Post checkpoint做任务微调，平均成功率50.1%。本文未核实逐任务微调示范量，不能据“少量示范”宣传推断具体条数。

另一个DROID陌生物体/场景、随机相机条件的5任务实验，每任务15次，表报87.1%；但正文提到部分完成给分，不能与严格全任务成功率直接并列。SO100表明确使用部分分，均值56.7%。

来源：[论文，§3、§4、§6.2–6.3、表6–7](https://arxiv.org/html/2605.02881v1)。

对我们的启发：即便有广泛预训练，真实新任务仍需要认真适配和测试；同时也不应从零训练一套基础VLA来证明我们的经验生产机制。

### 4.6 π0.7：把专家经验蒸馏进统一策略，接近我们的长期愿景

π0.7把示范、人工纠错、自主经验和非机器人数据混合训练，增加质量、速度、子任务和视觉目标等条件；其中包含RL专家生成的经验。它不是把所有数据无区分地做行为克隆，也不等于统一模型全部靠在线RL训练。

双UR5e叠衬衫实验没有该机器人上的折衣训练数据，带生成视觉子目标的π0.7报告80%成功率。条件是衬衫已在桌上铺平，目标机器人在其他任务上有训练数据，不能称完全陌生机械臂。人类比较为10名操作员、每人3次；模型测试分母本次未核实。总预训练小时数未从已核查材料获得。

来源：[论文，§VI、§IX、附录F](https://www.pi.website/download/pi07.pdf)。

另一个直接相关机制是先由人逐步语言指导新任务，再用这些记录训练高层策略，取代在线人工指导。[官方实例](https://www.pi.website/blog/pi07)

对我们的启发：人的解释可以成为高层策略训练数据；真实运动经验可以进入动作策略。不能要求一份文字skill同时承载这两类能力。

## 5. 从这些结果能得到什么，不能得到什么

跨论文的百分比不能排一张“最强模型榜”。SWE-bench检查软件修复，AppWorld检查模拟应用状态，LIBERO检查仿真任务，真实机器人实验又有不同对象、初始状态和计分规则。本文关注的是各论文内部的增益及其条件。

可以支持的判断是：技能库并不过时，但学生是否会使用它是独立问题；SFT是必要的竞争路线，不能跳过；机器人RL可以快速改善某些已有能力；强基础策略与人工反馈仍是许多高效果系统的起点。没有这些前提，“让学生自己试，成功就奖励”不构成可行训练方案。

目前不能据这些结果宣称：任何便宜VLM拿到我们的skill都会具备顶模加人类的能力；几小时能从零获得泛化翻转；软件Agent RL的效果可以直接迁移到机械臂；某个物体100次全成功等于Flip Anything。

## 6. 对现有开发流程的具体修改建议

### 6.1 把每天的工作从“维护skill”改为“积累可验证经验”

仍然由人和顶模解决难例，但每次尝试都保存同步图像、本体状态、动作与时间戳、代码/API版本、执行反馈、成功判定、失败位置和人类介入。文本解释关联到真实片段。失败经验不直接作为正确动作监督，而是保留给错误分析、恢复学习和奖励/价值学习。

一次成功可以产生三种可选资产：文字与代码skill；教师的高层交互训练样本；可用于BC或RL的机器人动作轨迹。先把原始记录统一，资产可以按需要生成，不必同时训练三套系统。

### 6.2 优先检验两条主路线，不预先堆成完整分层架构

| 路线 | 初始实现 | 要回答的问题 |
|---|---|---|
| A：便宜VLM＋skill/code | 保留现有思路；再加入相同学生的教师轨迹SFT版本 | 学生缺少经验，还是缺少使用经验的能力？ |
| B：已有动作策略＋示范/纠错 | 优先适配现有开源policy；对固定困难阶段尝试小策略RL | 高层思路已经正确时，控制学习能否消除失败？ |

Agent RL应在A已经具备基本成功率、有可靠物理奖励、能稳定生成rollout之后加入。小策略RL应在B能完成部分动作之后加入。若现成策略已经稳健完成任务，就直接测试它，不为突出我们的方法故意选弱基线。

是否组合A与B，由失败分析决定。不同层同时变化会让结果无法归因：上层和执行器都升级后，成功率增长不能被单独算作技能迁移收益。

### 6.3 第一轮比较应包括哪些条件

在同一学生、接口和固定低层执行器下比较：基础学生；学生＋冻结skill/code；教师轨迹SFT；SFT＋同一skill/code。训练和上下文材料均来自同一开发对象集合，报告各自新增人时与交互量。若这四组还不能确定收益，先不要上线Agent RL。

另外固定高层决策，在同一任务分布下比较参数化脚本、示范学习策略、示范学习＋纠错/小策略RL。这条实验比较执行能力，不能和上一条混成一个总表后宣称是同一种知识迁移。

加RL时保留“收集同样多数据、仅用成功及纠错片段继续SFT/BC”的基线。否则多交互带来的改进会被误算成RL算法收益。回放相同数据的比较用于隔离学习目标；允许各自采集数据的比较用于比较整体学习效率，两者分开报告。

### 6.4 Flip Anything的测试条件应比“学会一个翻转动作”更严格

先定义任务范围与成功标准：指定哪一面朝上、允许哪些工具和接触方式、物体是否需要完整留在目标区域、最终稳定多久、回合时限和重试数。球体等无法定义目标面的对象应预先排除，不能失败后再从分母删掉。

物体按物理属性和策略需求划分开发集与盲测集：尺寸、厚度、形状、质量分布、摩擦、柔性等。分别报告见过物体的新姿态、未见实例、未见物理属性组合；跨机械臂另设一组，明确允许多少校准和适配数据。

至少区分两个协议。零适配测试冻结权重、库和参数，遇到新物体不人工修改。快速适配测试统一给定新示范条数、人工介入时间或机器人交互预算，画成功率随预算的曲线。人工接管后的完成记为辅助成功，不能混入自主成功。

主指标用对象宏平均自主成功率，并报告每物体尝试数和不确定性；补充首次成功所需交互、达到目标可靠性所需人时、每小时成功数、失败恢复率。把有效运动时间、物理重置、标注、训练和调试分别计时。对反复测同一个物体的数据按物体聚类处理，不当作大量独立新对象。

成功验证器应与策略分开审计，覆盖假成功、遮挡和翻后回落。开发时可以人工核验，但最终比较须使用一致判据，抽样盲审验证器误差。奖励可以逐步设计，最终评分标准应先固定。

## 7. 研究问题应怎样改写

不再预设成品只有一套文本skill库。更合理的问题是：人和强模型共同产生的操作经验，怎样以最少新增交互转移给更便宜的执行系统，并在新物体上保持有效？

经验可以进入上下文、模型权重或动作策略。最终成品至少应包含可复现的经验采集与验证流程、版本化技能/数据资产、明确支持的学生或策略，以及冻结盲测和快速适配基准。哪种资产真正必要，由对照结果决定。

如果只给skill已经达到相同效果，就保留简单方案；如果SFT明显更好，就不再把冻结权重当原则；如果策略学习解决了主要失败，就让它承担接触控制。研究价值来自证明经验怎样迁移、何时失效，以及比直接训练或直接调用强模型节省了什么，而不是来自流程里模块的数量。

## 8. 证据和复现缺口

本报告已核对主要训练方法、若干数据量和测试条件，但没有完成所有代码复现。RLT论文获取失败；PI基础训练规模和部分评测分母未完整核实；MolmoAct2逐任务微调样本量尚缺；Agent Lightning成绩对应的完整固定配置待归档。文中已把这些缺口保留，不能拿不完整公开信息反推出我们的确定资源预算。

真正立项前，应为选定的两三条基线固定论文版本、代码提交、权重来源、输入相机与控制接口，再完成一次本地运行验证。此时才确定训练规模和硬件需求，避免把论文中的“追加数据”误当成从零复现的全部成本。
